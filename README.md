# Password Strength Checker

พิมพ์รหัสผ่านมาเช็คความแข็งแรงแบบเรียลไทม์ — ประเมินจาก **entropy จริง** ไม่ใช่แค่นับความยาวหรือเช็คว่ามีตัวเลข/สัญลักษณ์หรือเปล่า ไม่มีรหัสผ่านอยู่ในใจ? สุ่มรหัสผ่านใหม่ได้ที่ [`/generator/`](generator/) (ดีไซน์แยกกันคนละธีม เชื่อมกันด้วยแถบลิงก์บนสุดของทั้งสองหน้า)

**Demo:** https://mynameisnampetch51-del.github.io/password-checker/ · [ตัวสุ่มรหัสผ่าน](https://mynameisnampetch51-del.github.io/password-checker/generator/)

## แนวคิด

Entropy วัดว่ารหัสผ่าน "เดายากแค่ไหน" จริงๆ ไม่ใช่แค่ "ดูซับซ้อนแค่ไหน" คำนวณจาก:

```
entropy (bits) = ความยาว × log2(ขนาด character set ที่ใช้)
```

ตัวอย่างที่ขัดสามัญสำนึกแต่จริง: `correct horse battery staple` (แค่ตัวพิมพ์เล็ก+เว้นวรรค) มี entropy สูงกว่า `Tr0ub4dor&3` (มีครบทุกประเภทตัวอักษร) เพราะ**ความยาวสำคัญกว่าความซับซ้อนของ character set** — นี่คือเหตุผลที่ NIST แนะนำ passphrase ยาวๆ แทนกฎ "ต้องมีตัวใหญ่+เลข+สัญลักษณ์"

แต่ entropy จากสูตรอย่างเดียวหลอกได้ (เช่น `qwertyuiop` มี charset เล็กแต่ยาว 10 ตัว) เลยต้องเช็ค pattern ที่ทำให้เดาง่ายเพิ่ม แล้วหักคะแนน:

| เช็ค | ทำอะไร | ผลถ้าเจอ |
|---|---|---|
| รหัสผ่านยอดฮิต | เทียบกับ list ~28 รหัสที่ถูกใช้/หลุดบ่อยที่สุด | บังคับ entropy ≤ 10 บิต |
| ตัวอักษรซ้ำติดกัน | นับ run ของตัวเดิม (เช่น `aaa`, `111`) ยาว ≥ 3 | หัก 12 บิต |
| เรียงต่อเนื่อง | นับ run ที่ charCode ห่างกัน ±1 (เช่น `abcd`, `4321`) ยาว ≥ 4 | หัก 12 บิต |
| รูปแบบคีย์บอร์ด | เทียบกับ substring ของแถวปุ่ม `qwertyuiop`/`asdfghjkl`/`zxcvbnm`/`1234567890` (รวมย้อนกลับ) ยาว ≥ 4 | หัก 12 บิต |

ระดับผล (หลังหักคะแนน): < 36 บิต = อ่อน, 36–59 = พอใช้, ≥ 60 = แข็งแรง

## ตัวสุ่มรหัสผ่าน (`/generator/`)

เดิมหน้านี้มีตัวสุ่มในตัว แต่ย้ายออกไปเป็นหน้าแยกต่างหากที่ [`generator/`](generator/) แล้ว — คนละดีไซน์ คนละธีม (พื้นถ่านร้อน+ember สไตล์เตาหลอม ต่างจากพื้นน้ำเงินของหน้านี้) ตั้งใจให้เป็นชิ้นโชว์ผลงานแยกในพอร์ต ไม่ใช่แค่ widget เสริม ทั้งสองหน้าเชื่อมกันด้วยแถบลิงก์บนสุด

ตรรกะการสุ่มยังอยู่ที่ `generator.js` ไฟล์เดียว (ใช้ร่วมกันผ่าน `<script src="../generator.js">` จากหน้า generator) — สุ่มด้วย `crypto.getRandomValues` (ไม่ใช้ `Math.random` — ไม่ปลอดภัยสำหรับสุ่มรหัสผ่านเพราะ PRNG ธรรมดาทำนายได้) แล้วเลือกตัวอักษรด้วย **rejection sampling** แทนการหาร mod ตรงๆ เพื่อกัน modulo bias

## เทคนิคที่ใช้

- แยก logic วิเคราะห์เป็น pure function ใน `rules.js` และแยกตัวสุ่มไว้ใน `generator.js` — คนละหน้าที่ เทส/แก้ไขทีละไฟล์ได้อิสระ (แนวทางเดียวกับ `phishing-detector/rules.js`)
- ไม่พึ่ง library ตรวจ pattern คีย์บอร์ด/entropy/สุ่มเลข — implement เอง
- ไม่มี `localStorage` หรือ network call ใดๆ — **ไม่บันทึกหรือส่งรหัสผ่านไปที่ไหนเลย** เป็นเจตนาการออกแบบ ไม่ใช่แค่ไม่ได้ทำ
- ดีไซน์แยกจากโปรเจกต์อื่นในพอร์ตโดยตั้งใจ (ปกติใช้ธีมแดง/ขาวร่วมกับ `phishing-detector/`, `to-do/`, `cube-net/`) — หน้านี้ใช้พื้นน้ำเงินเข้ม + IBM Plex Sans Thai/Mono และวาด**มาตรวัดเข็มเดียวด้วย SVG ล้วน** (ไม่พึ่ง library กราฟ) แทนแถบ progress ทั่วไป เพราะ entropy เป็นค่าที่วัดได้บนสเกลจริงที่มีโซนชื่อกำกับ (อ่อน/พอใช้/แข็งแรง) — ตรงกับสิ่งที่หน้าปัดเข็มสื่อสารได้ดีกว่าแถบ
- ขอบเขต 3 โซนสีบนหน้าปัดอ่านค่าจาก `LEVEL_THRESHOLDS` ใน `rules.js` โดยตรง ไม่ hardcode ซ้ำใน `app.js`

## ข้อจำกัด (พูดตรงๆ)

- List รหัสผ่านยอดฮิตมีแค่ ~28 รายการ (ของจริงอย่าง `rockyou.txt` มีหลายล้าน) เดโมนี้เน้นสาธิตแนวคิด ไม่ใช่ tool ตรวจจริงจัง
- ไม่เช็คว่าเป็นคำในดิกชันนารีหรือเปล่า (เช่น `elephant123` charset ผสมดูดี แต่เดาง่ายเพราะเป็นคำจริง+ตัวเลขต่อท้าย) — ต้องมี wordlist ถึงจะเช็คได้ ยังไม่ทำ
- Entropy เป็นการประมาณ ไม่ใช่การจำลอง attack จริง (เช่น brute-force กี่วินาทีที่ hardware ระดับไหน)
